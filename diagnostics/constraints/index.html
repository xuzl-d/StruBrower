通用约束：任意模型上的尺寸依赖与设计规则

不是「模板能调尺寸」，而是任何一棵特征树都能被 AI 后加约束：改一个源参数整组重算，违反设计规则就报警。

实现：shared/dimensions.js（尺寸寻址）· shared/constraints.js（求值）· server/ai/constraints.js（setConstraints 校验）· 复现命令 npm run constraint
模型
手写特征树，非模板

踏步阵列 + 立柱阵列，2 个特征；约束是后加的，没有一行生成器代码。

约束体积
731 B / 32 个数字

8 个尺寸别名 + 8 条驱动式 + 2 条校验式，几何一个字节都不复制。

验证
104 项全绿

寻址 / 求值 / 校验 / 拒绝 / 特征增删搬家，全走真实链路。

const CONSTRAINTS = {
  dimensions: [
    { name: '踏步数',   path: 'f1.count' },
    { name: '踏步高',   path: 'f1.height' },
    { name: '踏步起点Z', path: 'f1.translate.2' },
    { name: '踏步步距Z', path: 'f1.step.2' },
    { name: '立柱数',   path: 'f2.count' },
    { name: '立柱起点Z', path: 'f2.translate.2' },
    { name: '立柱步距Z', path: 'f2.step.2' },
    { name: '踏步步距Y', path: 'f1.step.1' },
  ],
  checks: [
    { expr: '踏步高 >= 0.14', message: '踏步高小于 140 mm，上楼梯容易踩空' },
    { expr: '踏步高 <= 0.18', message: '踏步高大于 180 mm，上楼吃力' },
  ],
};

3. 三种写法，三种职责

字段语义求值方式失败时
dimensions 给尺寸起名：别名 → 路径 只影响可读性，不参与计算 别名指向不存在的路径 → 服务端 400，列出可用路径
formulas 驱动式：这个数 = 表达式 依赖拓扑排序，一次算完写回 引用未知量 / 成环 / 一尺寸两公式 → 400
checks 校验式：写「要求」，为假即违规 算完再核对，不参与求解 语法错 → 400；不满足 → 进报告，模型不变

4. 可寻址的尺寸

写法含义例
f<n>.<字段>第 n 个特征的形状字段f2.height f2.radius f2.thickness
f<n>.<字段>.<下标>数组字段（变换、阵列、放样截面）f2.translate.2 f2.step.1 f2.sections.0.ellipse.rx
f<n>.count阵列数量（整数，1–192）f1.count
f<n>.fillet / shell / offset曲面修饰的标量f4.fillet
f<n>.g<m>.<字段>子特征组内的第 m 个特征f3.g1.height
param.<key>模型参数param.width
primitive.<key>基本体尺寸primitive.width

5. 已知边界

  • 只驱动特征字段，不做几何约束：相切 / 同心 / 共线需要 B-rep 拓扑命名与数值求解， 与「特征树每次重建」冲突，明确留白。
  • 单向：改源参数 → 派生量变；改派生尺寸会在下次重算时被覆盖（与 Revit 公式参数一致）。
  • 只校验、不夹取：违反 checks 的模型照样生成，问题进面板与报告。
  • 参数化构件只暴露 param.*：它的几何由生成器按参数重建，写特征字段会被下次重建吞掉。
  • 特征增删会自动搬家：插在 f2 前面的特征会把约束挪到 f3，被删特征上的约束直接清掉。
